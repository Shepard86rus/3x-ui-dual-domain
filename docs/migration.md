# Перенос сервера: `backup` и `restore` (0.6.4+)

Нужны, чтобы перенести свою установку на другой сервер (смена хостера, переезд, откат к снимку) и не создавать клиентов заново.

## Что попадает в архив
- БД панели: клиенты, инбаунды, настройки, подписки;
- `/root/.lucx-credentials` (адрес и пароль панели);
- конфиги nginx этой схемы и конфиги AmneziaWG;
- манифест с версиями (панель, xray, скрипт) и доменами;
- сертификаты — только если `backup --with-certs`.

**Не входят:** заглушки, Telegram-бот, сами программы (панель, xray, модуль AWG). Их ставит `install` на новом сервере.

## Важно знать
- Архив содержит ключи и всех клиентов. Храните как секрет. Пароль архива **восстановить нельзя**.
- Восстанавливайте **только свои** архивы: архив определяет конфиги nginx, AWG и xray с правами root.
- Не передавайте пароль в командной строке (`LUCX_BACKUP_PASS=…` остаётся в истории shell): скрипт спросит его сам.
- Версия панели на новом сервере должна быть **не ниже** версии в архиве, иначе `restore` откажется (обновите панель: `x-ui update`).
- Домены на новом сервере должны быть **теми же**, что были. Несовпадение — всегда отказ.
- Запускайте `restore` в `tmux`/`screen`: при обрыве SSH применение не прерывается, но так спокойнее.

## Порядок переноса
1. Старый сервер: `sudo bash 3x-ui-dual-domain.sh backup` → файл `/root/lucx-backup-….lucxbak`. Скачайте его на свой компьютер (`scp` или SFTP в Termius; под обычным пользователем скрипт напечатает команды копирования).
2. У регистратора направьте A-записи **всех** имён схемы на IP нового сервера и дождитесь, пока DNS обновится (проверка: `dig +short имя`).
3. Новый сервер: поставьте скрипт и выполните `install` с **теми же** доменами. Если на старом был XHTTP — `add-xhttp <то же имя>`.
4. Загрузите архив на новый сервер и выполните `sudo bash 3x-ui-dual-domain.sh restore файл.lucxbak`.
5. `sudo bash 3x-ui-dual-domain.sh healthcheck`, затем подключитесь с телефона. Если у старого сервера был бот — `add-bot` на новом.
6. Старый сервер выключите (или остановите там бота: один токен Telegram у двух серверов мешает друг другу).
7. Удалите `/root/.lucx-restore-backup-*` (страховочная копия, в ней секреты) и скачанный архив там, где он больше не нужен.

## Что делает `restore`
Проверяет пароль и целостность до любых изменений (при ошибке сервер не тронут), сверяет версии и домены, сохраняет страховочную копию текущего состояния в `/root/.lucx-restore-backup-…`, подменяет БД, `creds`, конфиги nginx и AWG, прописывает IP этого сервера в `listen` stream-роутера, открывает в ufw порты AWG из архива, перезапускает nginx и панель. При любом сбое или обрыве возвращает прежнее состояние.

Ключи: `--yes` (без вопроса), `--certs` (взять сертификаты из архива, если он делался с `--with-certs`), `--force` (пропустить только проверку версии панели; домены не обходятся).

## Если что-то не так
| Сообщение | Что делать |
|---|---|
| «неверный пароль или повреждённый архив» | проверьте пароль и целостность файла (скачивание не оборвалось); сервер не тронут |
| «версия панели здесь … НИЖЕ архивной» | `x-ui update`, затем повторите `restore` |
| «домены установки не совпадают» / «в архиве есть XHTTP-домен» | поставьте `install` с теми же именами (и `add-xhttp`), затем `restore` |
| «сертификата для … нет» | A-записи должны указывать на этот сервер до `install`; либо `backup --with-certs` и `restore --certs` |
| «nginx -t не прошёл» / «Откат …» | состояние возвращено; не перезагружайте сервер, если после отката появилось «nginx -t НЕ проходит»: смотрите путь страховочной копии в сообщении |
| после `restore` не подключается AWG | проверьте клиента; при необходимости перезагрузите сервер (модуль мог обновиться) |
| порт инбаунда не открыт | скрипт открывает только 22/80/443 и порты AWG; остальные порты из БД он перечисляет в конце — откройте нужные в `ufw` |

Команда бота `backup` копирует только БД панели и к этой схеме не относится.
