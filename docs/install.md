# Установка по порядку

| Этап | Что делаем | Где |
|---|---|---|
| 1 | Готовим сервер и DNS, обновляем систему | сервер, регистратор домена |
| 2 | Запускаем установщик | сервер |
| 3 | Дорабатываем панель вручную: AmneziaWG и ключи клиентов | панель в браузере |
| 4 | Проверяем сервер | сервер |
| 5 | Подключаем клиентов в приложениях | [clients.md](clients.md) |

## Этап 1. Подготовка

**Нужно заранее:** сервер с Ubuntu 22.04/24.04 (root), **два домена** (панельный и основной) с A-записями на IP
сервера — DNS должен резолвиться до установки — и, по желанию, третье имя для XHTTP (тоже с A-записью).

Обновите систему и перезагрузите сервер (на свежем сервере — первым делом), после ребута зайдите снова под root:

```bash
apt update && apt full-upgrade -y && reboot
```

## Этап 2. Установка

Скачайте скрипт на сервер (он остаётся там — все дальнейшие команды запускаются из этого файла, обычно в `/root`)
и запустите установку (скрипт интерактивный):

```bash
curl -fsSL https://github.com/Shepard86rus/3x-ui-dual-domain/releases/latest/download/3x-ui-dual-domain.sh -o 3x-ui-dual-domain.sh
bash 3x-ui-dual-domain.sh install
```

Он спросит: **домен панели**; **«домен-обложка Reality»** (в этой документации это **основной домен**, на который
идут клиенты); необязательное **третье имя для XHTTP** (Enter — пропустить, см. [xhttp.md](xhttp.md)); SubPath
панели; порт AmneziaWG (Enter = 52911); применить ли рекомендованные настройки подписок; версию панели (Enter =
последняя стабильная). База данных — SQLite (скрипт выставляет и проверяет это сам; PostgreSQL не поддерживается).
В самом конце — итоговый экран (адрес, логин и пароль панели, адреса подписок, что сделать дальше): **сохраните
его** — пароль понадобится на следующем этапе. Последним будет вопрос про опционального Telegram-бота — Enter
пропускает.

**Если в самом начале появился блок «Проверка ядра» (с v0.5.8).** Это значит, что на сервере устаревшее ядро (для
него уже нет заголовков) или система ждёт перезагрузки после обновления. Нажмите Enter: скрипт обновит систему
(`apt full-upgrade`) и перезагрузит сервер. SSH-сессия оборвётся — это нормально. Через минуту зайдите снова и
**запустите `install` ещё раз**: блока уже не будет, установка пройдёт до конца. Если выполнили этап 1 целиком,
этого блока, как правило, не будет. Отказались (`n`) — установка продолжится, но установщик панели сам обновит
ядро, и сервер может перезагрузиться посреди установки (тогда просто запустите `install` заново). Пропустить
проверку: `SKIP_KERNEL_PREFLIGHT=1 bash 3x-ui-dual-domain.sh install`.

**Если в конце появилось «⚠ СНАЧАЛА ПЕРЕЗАГРУЗИ СЕРВЕР»** — выполните `sudo reboot`: установлено новое ядро,
AmneziaWG заработает только после перезагрузки.

## Этап 3. Настройка панели вручную

### Что установщик уже сделал сам

Руками в панели ничего из этого повторять не нужно:

- создал инбаунды **VLESS+TLS (Vision)**, **Reality** (перед TLS на том же 443), **Hysteria2** (UDP/443) и, если вы
  задали третье имя, **XHTTP+Reality** — со всеми ключами и настройками;
- создал клиентов (`client1`, `client1-reality`, hy2-клиента и `client1-xhttp`) и сам импортировал их в таблицу
  панели (`x-ui migrate`): они сразу видны на странице «Клиенты». Но **ключи у них неполные**: у части пустые
  пароль и Hysteria Auth, а у `client1` ID подписки фиксированный (`primary`) — их нужно обновить (шаг 3.2);
- у инбаундов **VLESS** и **Hysteria2** задал «Стратегию адреса для ссылок» = «Пользовательская» и «Пользовательский
  адрес» = основной домен; в режиме TLS поставил **uTLS `firefox`**;
- на вопрос **«Применить рекомендованные настройки подписок?»** (Enter = да) включил подписку **Clash/Mihomo** с
  автоопределением по User-Agent и правилами из [`clash-universal.yaml`](../clash-universal.yaml) (клиенту нужен
  Mihomo ≥ 1.19), маршрутизацию **Happ** и **Incy** по профилям
  [hydraponique](https://github.com/hydraponique/roscomvpn-routing), скрыл настройки сервера (Happ) и URL подписки
  (Incy), включил DoH-резолв Incy и поставил название подписки, если вы его ввели;
- выпустил сертификаты Let's Encrypt, поставил decoy-сайты, nginx, ufw и fail2ban.

Отказались от рекомендованных настроек (ответили `n`) — подписки настраиваются в панели вручную (вкладки
«Clash / Mihomo», «Happ», «Incy» в настройках подписки). Если установщик предупредил, что импорт клиентов не удался,
выполните `systemctl stop x-ui && /usr/local/x-ui/x-ui migrate && systemctl start x-ui`.

### Шаг 3.1 — AmneziaWG

Установщик ставит модуль ядра и утилиты AWG, но сам инбаунд не создаёт:

1. Откройте панель (адрес, логин и пароль — на итоговом экране установщика) и войдите.
2. Страница **AmneziaWG** → **Enable** → порт (по умолчанию 52911, udp) → **Save**.
3. Панель → Инбаунды → «Изменить» у созданного AWG-инбаунда → вкладка **«Основное»**: «Стратегия адреса для
   ссылок» = **«Пользовательская»**, «Пользовательский адрес для ссылок» = **основной домен** (только имя, без
   `https://`, порта и `/`), остальное не трогать → «Сохранить изменения».

### Шаг 3.2 — обновите ключи у созданных клиентов

Панель → Клиенты → «Изменить клиента» → вкладка «Учетные данные»; для **каждого** клиента (в том числе `client1`)
сгенерируйте всё заново:

| Поле | Что делать |
|---|---|
| UUID | сгенерировать кнопкой ↻ |
| Пароль | сгенерировать кнопкой ↻ |
| ID подписки | сгенерировать кнопкой ↻ — по нему строится ссылка подписки (у `client1` до этого стоит `primary`) |
| Hysteria Auth | сгенерировать кнопкой ↻ |
| Flow | **только VLESS** (+TLS): `xtls-rprx-vision` (у созданных клиентов установщик ставит его сам; у новых клиентов выберите вручную). Hysteria2 и AWG — flow не нужен |

**Сохранить** → повторить для каждого клиента. Новых клиентов добавляйте так же: Клиенты → «Добавить» и заполните
те же поля.

> ℹ️ Ссылки подписок и ключи меняются после этого шага, поэтому **раздавайте клиентам ссылки только после него** —
> иначе выданные раньше ссылки перестанут работать.

<details>
<summary>Ноды, установленные до 0.5.3 (или если установщик предупредил, что поля не записал): адрес для ссылок и uTLS вручную</summary>

**Адрес для ссылок в инбаундах.** Панель собирает ссылки клиентов
из адреса инбаунда. У **VLESS** он внутренний: поле «Адрес» = `127.0.0.1`
(инбаунд слушает только loopback, снаружи его не видно), и без настройки в
ссылке окажется `127.0.0.1` — клиент не подключится. У **Hysteria2** и
**AWG** поле «Адрес» пустое (они слушают публично), но и им нужно явно
указать основной домен, чтобы в ссылки не попал другой адрес (например,
панельный). Поэтому в каждом инбаунде задаётся, какой адрес подставлять.

Панель → Инбаунды → кнопка «Изменить» у инбаунда → окно «Изменить
подключение» → вкладка **«Основное»**:

| Поле | Что сделать |
|---|---|
| Адрес | **не трогать** (у VLESS `127.0.0.1`, у Hysteria2/AWG пусто) |
| Стратегия адреса для ссылок | выбрать **«Пользовательская»** |
| Пользовательский адрес для ссылок | вписать **основной домен** — только имя, без `https://`, без порта и без `/` (пример: `example.com`) |
| Порт | **не трогать** (у VLESS и Hysteria2 это 443, у AWG — свой порт) |

Остальные поля вкладки оставьте как есть, нажмите **«Сохранить изменения»**.
Повторите для **каждого** инбаунда (VLESS, Hysteria2, AWG), в каждом впишите
один и тот же основной домен. Не панельный домен — именно основной: на нём
принимаются клиентские подключения.


**Отпечаток uTLS (для VLESS и Hysteria2).** Клиенты из России
подключаются с отпечатком `firefox` (`fp=firefox` в ссылке), поэтому в
инбаунде он должен быть выбран так же. Панель → Инбаунды → «Изменить» у
инбаунда → вкладка **«Безопасность»** (режим безопасности — **TLS**):

| Поле | Что сделать |
|---|---|
| uTLS | выбрать **firefox** |

Остальное на вкладке («SNI», версии 1.2/1.3, ALPN `http/1.1`, пути к
сертификату) **не трогайте** — это настроил установщик. Нажмите
**«Сохранить изменения»**. Повторите для VLESS и для Hysteria2.

## Этап 4. Проверка

```bash
bash 3x-ui-dual-domain.sh healthcheck
```

Это автопроверка всего сервера (90+ проверок): сервисы, порты, firewall, сертификаты, decoy-сайты, БД, подписки,
AWG, бот, открытые порты. В ответ — «N проверок ОК, M провалено» и список проблем.

> ⚠️ **healthcheck — только после этапа 3.** До настройки панели часть проверок покажет предупреждения или FAIL
> (AWG не включён, ключи клиентов не обновлены) — это ожидаемо, а не поломка. Порядок: `install` → этап 3 (AWG и
> ключи клиентов) → `healthcheck`.

Проверка открытых портов (изнутри и снаружи) — отдельный проект:
[ext-port-check](https://github.com/Shepard86rus/ext-port-check).

## Этап 5. Подключение клиентов

Установка закончена, но пользоваться сервером можно только через приложение-клиент. Какие приложения выбрать
(INCY, Clash Verge Rev), откуда брать ссылку подписки и как её добавить — в **[clients.md](clients.md)**.
