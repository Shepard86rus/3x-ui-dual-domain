Установщик и healthcheck для VPN-панели на одном сервере: два домена,
nginx SNI-роутинг на 443, режимы TLS/Reality, Hysteria2, AmneziaWG, подписки,
decoy-сайты, ufw + fail2ban. Опционально — Telegram-бот управления нодой
с карточками-кнопками.

## Как устроена схема

- Снаружи слушает **только nginx на 443** (TCP): по SNI из ClientHello он
  маршрутизирует трафик на xray, слушающий на loopback (proxy protocol),
  а «чужие» подключения и браузеры получают decoy-сайты с валидным сертификатом.
- Панель и подписки доступны только через nginx по своим домену/пути,
  на публичных портах не висят.
- Hysteria2 работает на UDP/443, AmneziaWG — на отдельном UDP-порту
  (генерируется случайно при установке).
- VLESS в режиме TLS ставится с `flow=xtls-rprx-vision` (убирает отпечаток
  вложенного TLS); у старых клиентов без flow подключение не пройдёт —
  пересоздайте/обновите их. Decoy-сайты отдают `Strict-Transport-Security` (HSTS).
- ufw закрыт наглухо, кроме 22/80/443 TCP + 443 UDP + AWG-порта;
  fail2ban следит за SSH и панелью.

## Что нужно заранее

- Сервер с **Ubuntu 22.04/24.04** и доступом под root.
- **Два домена** (или два имени) с A-записями на IP сервера. DNS должен
  резолвиться **до** установки — скрипт проверяет и без него не продолжит.

| Домен | Для чего служит | Пример |
|---|---|---|
| **Панельный** | доступ к панели (только ты), decoy-сайт №1, подписки клиентов (`subURI`) | `panel.example.com` |
| **Основной** | клиентские подключения vless/hy2, decoy-сайт №2 | `example.com` |

Почему нельзя обойтись одним: nginx на 443 маршрутизирует трафик **по SNI** —
каждому сервису нужно собственное имя. Панели вдобавок нужно отдельное имя для
опсеки: адрес панели не светится на домене, куда ходят клиенты.

### Режим 443: TLS или Reality

При `install` скрипт спросит режим работы порта 443: **[1] VLESS+TLS** (по
умолчанию, Enter) или **[2] Reality**. Если сомневаетесь — берите TLS.

> [!WARNING]
> **На клиенте Clash/Mihomo Reality из России работает только с отпечатком
> `firefox` и на ядре Xray не выше `v26.7.28`.** Это результат наших проверок на
> Clash/Mihomo: на более новых ядрах (в том числе на тех, что ставит актуальная
> панель) Reality там не работает, другие отпечатки режутся. На других клиентах
> (Happ, v2rayN, Incy и т. д.) поведение может отличаться — проверяйте у себя.
> Поэтому на свежей установке выбирайте **TLS**, а Reality — только если
> понимаете, зачем он вам (клиенты вне РФ, либо вы осознанно держите старое ядро).

| | TLS | Reality |
|---|---|---|
| Как работает | nginx на 443 только маршрутизирует по SNI (TLS не расшифровывает); TLS с вашим сертификатом терминирует сам xray на loopback, не-VLESS трафик после рукопожатия уходит на decoy №2 | xray сам терминирует Reality-протокол, «чужие» подключения — на decoy №2 |
| Настройка клиента | vless+TLS, raw, fp=firefox, `flow=xtls-rprx-vision` | vless+Reality, `flow=xtls-rprx-vision`, **fp=firefox** (для РФ; по умолчанию в панели стоит `chrome` — для РФ его нужно сменить на `firefox`) |

Передумать можно в любой момент: `add-vls` (→ TLS) или `add-reality` (→ Reality)
переключает режим в обе стороны **без переустановки**, клиенты и ключи сохраняются.

#### Если выбрали Reality

Что делает установщик в этом режиме:

- xray сам терминирует Reality на loopback `127.0.0.1:443` (nginx на 443 по-прежнему
  только маршрутизирует по SNI), свой сертификат для VLESS в xray не нужен (сертификат домена использует nginx-decoy).
- **Сайт-цель (`dest`) — собственный nginx-decoy на этом же сервере**
  (`127.0.0.1:8444`, ваш основной домен), а не чужой популярный сайт. Зонды и
  браузеры, не прошедшие проверку Reality, получают этот decoy. Такой вариант
  (своя цель) в документации авторов Reality не описан, поэтому его поведение
  на практике проверяйте сами.
- `serverNames` = основной домен, создаются ключи x25519 и два `shortId`;
  у клиента включён `flow=xtls-rprx-vision`.
- В итоге установки ссылка не печатается, а выводятся: `Client UUID`, `Short IDs`,
  `Public key`, `ServerName` (они же сохраняются в `/root/.lucx-credentials`).
  Клиентам удобнее выдавать **подписку** из панели.

Что отличается в ручной настройке панели (раздел «Установка», пункт 3):

- **Адрес для ссылок** (с v0.5.3) установщик задаёт сам, как в TLS-режиме.
- **uTLS `firefox`** — **только для режима TLS** (ставится установщиком). В Reality
  на вкладке «Безопасность» выбрано «Reality», настройки сертификата не нужны;
  отпечаток и ключи не меняйте.
- **Шаг 2 (клиенты)** — как в TLS-режиме; `Flow` оставьте `xtls-rprx-vision`.

Переключение туда-обратно:

- `add-reality` возвращает **сохранённые ранее** ключи и `shortId` (из
  `/root/.lucx-mode-backup/`), либо генерирует новые, если сохранения нет.
- `add-vls` переводит обратно на TLS.
- Клиенты на подписке обновятся сами; ручные ссылки нужно перевыпустить.
- Сразу после переключения запустите `healthcheck`: проверки [6] и [7] учитывают режим.

Не меняйте режим руками в панели (переключатель «Безопасность» TLS ⇄ Reality):
см. «Что можно и нельзя в панели».

## Установка

1. Скачайте скрипт на сервер (он остаётся там — все дальнейшие команды
   запускаются из этого файла, обычно в `/root`):

   ```bash
   curl -fsSL https://raw.githubusercontent.com/Shepard86rus/3x-ui-dual-domain/main/3x-ui-dual-domain.sh -o 3x-ui-dual-domain.sh
   ```

2. Запустите установку (скрипт интерактивный):

   ```bash
   bash 3x-ui-dual-domain.sh install
   ```

   Он спросит домены и режим 443, предложит выбор версии панели (Enter =
   последняя стабильная), сохранит креды в `/root/.lucx-credentials` (mode 600)
   и напечатает итог. База данных — SQLite (скрипт выставляет и проверяет это
   сам; PostgreSQL не поддерживается). В конце предложит опционального
   Telegram-бота — Enter пропускает.

3. **Доделайте панель вручную** (с v0.5.3 остаётся два шага). Установщик теперь
   сам делает то, что раньше правилось в панели руками:

   - у инбаундов **VLESS** и **Hysteria2** задаёт «Стратегию адреса для ссылок» =
     «Пользовательская» и «Пользовательский адрес» = основной домен;
   - в режиме TLS ставит **uTLS `firefox`** у VLESS и Hysteria2;
   - на вопрос **«Применить рекомендованные настройки подписок?»** (Enter = да)
     включает подписку **Clash/Mihomo** с автоопределением по User-Agent и правилами
     из [`clash-universal.yaml`](clash-universal.yaml) (клиенту нужен Mihomo ≥ 1.19),
     маршрутизацию **Happ** и **Incy** по профилям
     [hydraponique](https://github.com/hydraponique/roscomvpn-routing), скрывает
     настройки сервера (Happ) и URL подписки (Incy), включает DoH-резолв Incy и
     ставит название подписки, если вы его ввели.

   Отказались от рекомендованных настроек (ответили `n`) — подписки настраиваются
   в панели вручную (вкладки «Clash / Mihomo», «Happ», «Incy» в настройках подписки).

   **Шаг 1 — AWG-инбаунд** (если вы создали его в панели): установщик его не создаёт и
   его адрес не задаёт. Панель → Инбаунды → «Изменить» у AWG-инбаунда → вкладка
   **«Основное»**: «Стратегия адреса для ссылок» = **«Пользовательская»**,
   «Пользовательский адрес для ссылок» = **основной домен** (только имя, без
   `https://`, порта и `/`), остальное не трогать → «Сохранить изменения».

   **Шаг 2 — клиенты**: первый клиент `client1` установщик создаёт и сам импортирует
   в таблицу панели (команда `x-ui migrate`), поэтому он сразу виден на странице
   «Клиенты». Если установщик предупредил, что импорт не удался, выполните
   `systemctl stop x-ui && /usr/local/x-ui/x-ui migrate && systemctl start x-ui`.
   Дальше — Панель → Клиенты → «Изменить клиента» → вкладка «Учетные данные»:

   | Поле | Что делать |
   |---|---|
   | UUID | сгенерировать кнопкой ↻ |
   | Пароль | сгенерировать кнопкой ↻ |
   | ID подписки | сгенерировать кнопкой ↻ — по нему строится ссылка подписки |
   | Hysteria Auth | сгенерировать кнопкой ↻ |
   | Flow | **только VLESS** (+TLS): должен быть `xtls-rprx-vision` (у первого клиента `client1` установщик ставит его сам; у новых клиентов выберите вручную). Hysteria2 и AWG — flow не нужен |

   **Сохранить** → повторить для каждого клиента.


   <details>
   <summary>Ноды, установленные до 0.5.3 (или если установщик предупредил, что поля не записал): адрес для ссылок и uTLS вручную</summary>

   **Адрес для ссылок в инбаундах.** Панель собирает ссылки клиентов
   из адреса инбаунда. У **VLESS** он внутренний: поле «Адрес» = `127.0.0.1`
   (инбаунд слушает только loopback, снаружи его не видно), и без настройки в
   ссылке окажется `127.0.0.1` — клиент не подключится. У **Hysteria2** и
   **AWG** поле «Адрес» пустое (они слушают публично), но и им нужно явно
   указать основной домен, чтобы в ссылки не попал другой адрес (например,
   панельный). Поэтому в каждом инбаунде задаётся, какой адрес подставлять.

   Панель → Инбаунды → кнопка «Изменить» у инбаунда → окно «Изменить
   подключение» → вкладка **«Основное»**:

   | Поле | Что сделать |
   |---|---|
   | Адрес | **не трогать** (у VLESS `127.0.0.1`, у Hysteria2/AWG пусто) |
   | Стратегия адреса для ссылок | выбрать **«Пользовательская»** |
   | Пользовательский адрес для ссылок | вписать **основной домен** — только имя, без `https://`, без порта и без `/` (пример: `example.com`) |
   | Порт | **не трогать** (у VLESS и Hysteria2 это 443, у AWG — свой порт) |

   Остальные поля вкладки оставьте как есть, нажмите **«Сохранить изменения»**.
   Повторите для **каждого** инбаунда (VLESS, Hysteria2, AWG), в каждом впишите
   один и тот же основной домен. Не панельный домен — именно основной: на нём
   принимаются клиентские подключения.


   **Отпечаток uTLS (для VLESS и Hysteria2).** Клиенты из России
   подключаются с отпечатком `firefox` (`fp=firefox` в ссылке), поэтому в
   инбаунде он должен быть выбран так же. Панель → Инбаунды → «Изменить» у
   инбаунда → вкладка **«Безопасность»** (режим безопасности — **TLS**):

   | Поле | Что сделать |
   |---|---|
   | uTLS | выбрать **firefox** |

   Остальное на вкладке («SNI», версии 1.2/1.3, ALPN `http/1.1`, пути к
   сертификату) **не трогайте** — это настроил установщик. Нажмите
   **«Сохранить изменения»**. Повторите для VLESS и для Hysteria2.


   </details>

4. Запустите проверку:

   ```bash
   bash 3x-ui-dual-domain.sh healthcheck
   ```

   Это автопроверка всего сервера: сервисы, порты, firewall, сертификаты,
   decoy-сайты, БД, подписки, AWG, бот, открытые порты. В ответ — «N проверок
   ОК, M провалено» и список проблем.

> ⚠️ **healthcheck — только после настройки панели (пункт 3 выше).**
> До заполнения полей проверка покажет FAIL'ы (ключей ещё нет) — это
> ожидаемо, а не поломка. Порядок: `install` → заполнение клиентов →
> остальная настройка панели (AWG и т.д.) → `healthcheck`.

Проверка открытых портов (изнутри и снаружи) — отдельный проект:
[ext-port-check](https://github.com/Shepard86rus/ext-port-check).

## Что можно и нельзя в панели

Панель — полноценная, но схема держится на соглашениях, которые прописал
установщик. Краткое правило: **клиентов трогать можно; инбаунды, их режимы
и настройки ядра Xray в панели — не трогать.**

### ✅ Безопасно

- добавлять / удалять / переименовывать **клиентов** через панель;
- включать и настраивать **подписки** (`subURI`, `subAwgEnable`);
- настраивать **Инси** (автоопределение, Sort-Order, Hide-Url, DoH);
- менять **порт/путь панели** (штатный переезд, healthcheck это допускает);
- обновлять панель и ядро Xray через `x-ui update` (см. «Повседневная работа»).

### ❌ Ломает схему (проверено на живых серверах)

- **Нажимать «Masking» (caddy-layer4)** — перехватывает 443 у nginx: SNI-роутинг,
  панель и клиенты лягут. Healthcheck увидит перехват и выдаст WARN ([2]), но
  лучше не включать вообще.
- **Редактировать боевые инбаунды через форму и «Сохранить».** Форма
  перезаписывает `streamSettings` целиком: теряются `sockopt.acceptProxyProtocol`
  и массив `settings.clients` — инбаунд остаётся без единого клиента, весь
  трафик уходит в fallback. Правка инбаунда — только через **«Расширенный
  шаблон» (JSON)** или скрипт.
- **Переключать режим 443 (TLS ⇄ Reality) руками в панели** — сломаешь сразу три
  вещи: 1) **decoy №2** (fallback уедет — сайт отдаст обрыв вместо страницы),
  2) **proxy protocol** (реальные IP клиентов превратятся в 127.0.0.1),
  3) **клиентов инбаунда** (`settings.clients` перезапишутся — все ссылки
  перестанут работать). Перенос схемы целиком — только командами `add-vls` /
  `add-reality`.
- **Вешать инбаунды/сайдкары на порт 8443** — он занят внутренним вхостом
  панели (nginx на 127.0.0.1:8443); сайдкар на 8443 уходит в краш-луп.
  Свободные альтернативы: 2087, 2083, 9443.
- **Делать «двойной vless» (TLS + Reality) за одним 443** — БД панели хранит
  один порт на инбаунд, отдельного внешнего порта в схеме нет; клиентская
  ссылка сгенерируется с внутренним портом. Разные режимы — на разных серверах.
- **Править «Исходящие»/«Маршрутизацию» без кнопки «Сохранить».** Диалоги
  панели держат изменения только в превью: без «Сохранить» слева вверху и
  перезапуска панели всё исчезает.

### ➕ Хочешь добавить новый протокол? Правила выживания

Скрипт настраивает и проверяет только связку **vless+TLS / Hysteria2 /
AmneziaWG** — всё остальное добавляй по правилам:

- **не трогай существующие инбаунды** — правка через форму ломает их (см. выше);
- **новый протокол — только на свободный порт**: не 443 (SNI-роутинг), не 8443
  (панель) и не занятые схемой;
- помни: **xray один на все инбаунды** — один кривой новый инбаунд роняет ВСЕ
  подключения разом, а не только новый;
- после каждого изменения — `healthcheck`.

Если протокол нужен, а уверенности нет — опиши кейс в ишуи репозитория.

## Повседневная работа

### Команды

| Команда | Что делает |
|---|---|
| `bash 3x-ui-dual-domain.sh install` | полная установка с нуля |
| `bash 3x-ui-dual-domain.sh healthcheck` | 60+ проверок: сервисы, порты, ufw, nginx, серты, decoys, БД, подписки, AWG, бот, скан открытых портов |
| `bash 3x-ui-dual-domain.sh upgrade` | обновить сам этот скрипт до новейшей версии с репозитория |
| `bash 3x-ui-dual-domain.sh add-vls` | перевод схемы на TLS (из Reality), с fallback-вхостом |
| `bash 3x-ui-dual-domain.sh add-reality` | перевод схемы на Reality (из TLS) |
| `bash 3x-ui-dual-domain.sh add-hy2` | добавление Hysteria2-инбаунда (с preflight-проверкой порта) |
| `bash 3x-ui-dual-domain.sh add-bot` | поставить/обновить Telegram-бота управления (env не затирает) |
| `bash 3x-ui-dual-domain.sh remove-bot` | удалить Telegram-бота |
| `bash 3x-ui-dual-domain.sh add-swap [--size 512M\|1G\|2G]` | опционально: swap-файл как страховка от OOM на ноде с малой памятью (не вызывается из install) |
| `bash 3x-ui-dual-domain.sh remove-swap` | убрать swap-файл, созданный add-swap |
| `bash 3x-ui-dual-domain.sh rebind-ip` | сервер сменил IP — перепрописать конфиги |

### Обновление скрипта

```bash
bash 3x-ui-dual-domain.sh upgrade
```

`upgrade` всегда скачивает последнюю версию из ветки `main` (выбора версии нет).
Номера версий и релизы — на странице [Releases](https://github.com/Shepard86rus/3x-ui-dual-domain/releases);
версии вида `v0.x.y` в тексте — это версии самого скрипта (см. шапку файла).

### Обновление панели

```bash
x-ui update
bash 3x-ui-dual-domain.sh healthcheck
```

Ядро Xray приезжает вместе с панелью. **Неинтерактивно** (cron/скрипты, без
терминала) — обновление задаёт **два вопроса**: подтверждение (`y`) и
обязательное SSL-меню (`4` = Skip SSL — панель за вашим nginx). Без ответов:
подтверждение = тихая отмена, а пустой ответ в SSL-меню ставит Let's Encrypt
через порт 80 и зависает. Правильно:

```bash
printf 'y\n4\n' | x-ui update
```

После обновления проверьте факт, а не exit-код — версия должна смениться:

```bash
grep -aoE 'v3\.[0-9]+\.[0-9]+-lucx\.[0-9]+' /usr/local/x-ui/x-ui | tail -1
```

Начиная с панели **lucx.291** SSL-меню при обновлении исчезло — достаточно `y`
(старый вариант `y\n4\n` тоже работает: лишняя «4» безвредна).

**Про AWG:** начиная с панели **lucx.292** юнит x-ui сам разрешает запись в
`/etc/amnezia`, поэтому скрипт v0.5.0+ никаких drop-in не ставит. На панели
**lucx.291** AWG без такого исключения не пишет конфиги — обновите панель до
lucx.292+. Drop-in `20-awg-amnezia.conf`, поставленный скриптом v0.4.9,
безвреден: скрипт его не трогает, при желании можно удалить вручную
(`rm` + `systemctl daemon-reload`).

Патч-релизы своей минорной линии безопасны. Перед мажорными релизами
(смена схемы БД) сверьтесь с release notes панели — миграции необратимы.

### Переезд на новый IP

У регистратора поменяйте A-записи, затем:

```bash
bash 3x-ui-dual-domain.sh rebind-ip
```

## Telegram-бот

Опция. В конце `install` скрипт спросит, поставить ли Telegram-бота для
управления этой нодой. По умолчанию — **нет**: Enter пропускает шаг. Панель
прекрасно живёт и без бота. Поставить позже — `add-bot`, убрать — `remove-bot`.

**Один бот = одна нода.** В Telegram вы получаете карточку с кнопками:

- 📊 Статус / 🔢 Версии / 💾 Диск / 📜 Лог x-ui
- 🩺 Healthcheck / 🔐 Бэкап БД
- ♻ Рестарт панели / ♻ Рестарт xray
- ⬆ Обновление скрипта (upgrade) / ⬆ Обновление панели (x-ui update)
- ➕ Клиент / 🗑 Удалить клиента / 📋 Список — только если вписан API-токен панели (см. ниже)

Опасные кнопки работают только после подтверждения «✅ Да» (живёт 120 секунд).
На каждое действие бот отвечает сообщением с префиксом имени ноды — удобно,
если ботов несколько на разных серверах.

### Как получить токен бота

1. В Telegram: **@BotFather** → `/newbot` → имя → username (должен кончаться на `bot`).
2. BotFather пришлёт токен вида `1234567890:AAH7...` — его и вписываете в
   install. Ввод скрыт (как пароль): вставили — на экране пусто — Enter.
3. Свой Telegram ID подскажет **@userinfobot**. Можно оставить пустым — тогда
   бот работает в режиме обучения: на `/start` пришлёт `ACCESS_CODE:
   chat_id=...`, число вписываете в `/etc/tgbot/env` (`CHAT_ID=...`) и
   `systemctl restart tgbot`.

Имя ноды (шапка карточки и префикс ответов) — по умолчанию hostname; Enter при
повторных запусках оставляет как есть.

### Управление клиентами из бота (v0.5.1, опционально)

«➕ Клиент» создаёт одну карточку клиента сразу с двумя протоколами
(VLESS + Hysteria2) и присылает **одну ссылку-подписку**, по которой приложение
получает оба. Мастер: имя → лимит IP → срок (+30/+90/+365 дней, без срока или
дата `ДД.ММ.ГГГГ ЧЧ:ММ` в поясе `CLIENT_TZ`, по умолчанию Asia/Yekaterinburg)
→ подтверждение. Лимит трафика не задаётся. VLESS-клиенты создаются с
`flow=xtls-rprx-vision`.

Чтобы включить, нужен **API-токен панели** (scope `admin`), который вставляется
при `add-bot`. Без токена кнопок управления клиентами нет.

**Как создать токен в панели:**

1. Откройте панель → **Настройки панели → Учётная запись**.
2. Найдите блок **API-токены** и нажмите **«Новый токен»**.
3. Впишите имя (например `tgbot`) и подтвердите — панель создаёт токен со scope `admin`.
4. **Скопируйте токен сразу**: он показывается один раз, дальше хранится только его хэш.
5. Выполните `bash 3x-ui-dual-domain.sh add-bot`. Три первых вопроса (токен
   бота, Telegram ID, название ноды) можно пропустить Enter'ом — старые значения
   сохранятся, — а на вопросе «API-токен панели» вставьте токен (ввод скрыт).

Токен можно выпустить и из консоли на самой ноде (значение появится в выводе один раз):

```bash
/usr/local/x-ui/x-ui setting -getApiToken -tokenName tgbot -tokenScope admin
```

Токен хранится в `/etc/tgbot/env` (права 600) и передаётся curl не в аргументах.
Проверка — `healthcheck`, пункт [12]: «API-токен панели принят». Какие инбаунды
цепляются, можно задать `CLIENT_INBOUNDS=1,2` в env (по умолчанию — все
включённые vless/hysteria из БД; список виден на шаге подтверждения).

**Отозвать токен:** в том же блоке API-токенов панели, затем удалить строку
`PANEL_API_TOKEN=` из `/etc/tgbot/env` и `systemctl restart tgbot`.

### Что ставится

`/etc/tgbot/env` (права 600) — `TOKEN`, `CHAT_ID`, `NODE_NAME`, `SCRIPT_PATH`
(и `PANEL_API_TOKEN`, если включено управление клиентами); тело бота
`/opt/tgbot/tgbot.sh` (bash, зависимости curl + jq); systemd-юнит `tgbot` —
включается только если токен вписан. **Ни одного нового открытого порта**: бот
сам ходит в api.telegram.org (long polling), ufw не меняется.

`add-bot` ставит бота на живую установку и обновляет его тело после `upgrade`
скрипта: пустые ответы сохраняют существующий env, непустые — заменяют (так
ротируется токен); живой сервис перезапускается сам. `remove-bot` сносит всё.
Проверка — `healthcheck`, пункт [12]: сервис, автозапуск, токен, whitelist,
версия тела, а при заданном API-токене — принимает ли панель токен. Если бот
не ставился — строка-пропуск, не FAIL.

### Безопасность — прочитайте

- **Токен бота = root-доступ к серверу** (кнопка upgrade исполняет код из main).
  Храните как пароль: утёк — @BotFather → `/mybots` → API Token → Revoke, новый
  токен в env и `systemctl restart tgbot`.
- **Токен admin панели = полное управление панелью**: храните как пароль.
- Whitelist по chat_id: чужие молча игнорируются. **Вписывайте личный ID, а не
  ID группы** — в группе бот выполнял бы команды для любого участника.
- Словарь команд фиксированный, произвольного `/exec` нет, аргументы из чата
  в shell не попадают.
- Токен бота проходит в аргументах curl (виден в `ps` в момент запроса) —
  на одиночном root-сервере это норма.

## Если что-то не так

Первым делом — `bash 3x-ui-dual-domain.sh healthcheck`: он покажет, что именно
сломалось.

| Симптом | Причина / лечение |
|---|---|
| Decoy №2 отдаёт 301-цикл в TLS-режиме | fallback уехал на :80 — чинится в v0.4.0+; обновите скрипт (`upgrade`) |
| xray в краш-лупе, в логе `invalid geodata asset file` | зеркало отдало 404 на гео-файл — гео-страж (v0.4.2+) докачивает сам; проверьте healthcheck |
| AWG-инбаунд не поднимается, `interface already up` | баг панелей до lucx.289 — обновите панель (`x-ui update`), она поднимет осиротевший интерфейс за ≤10 с |
| healthcheck FAIL «слушает и разрешён ufw, но НЕ из схемы» | что-то слушает публичный порт вне белого списка (22/80/443) — сайдкар/тестовый инбаунд; уберите или внесите в `/root/.lucx-public-tcp-ports.txt` осознанно |
| Пропали клиенты инбаунда после правки через форму | перезапись `settings.clients` — клиенты восстанавливаются из бэкапа БД (`/etc/x-ui/x-ui.db`), инбаунд пересоздать |
| Всё сломалось после нажатия «Masking» | см. красное предупреждение вверху; запустите `healthcheck`, не чините вручную |
| Клиент не подключается, нет flow | у VLESS+TLS должен быть `flow=xtls-rprx-vision` — пересоздайте/обновите клиента |
