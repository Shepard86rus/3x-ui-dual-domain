# Сервер сменил IP

Бывает, что хостер выдаёт другой публичный IP (переезд, пересоздание сервера, смена адреса).
Схема привязана к IP только в одном месте: nginx слушает `listen <IP>:443;` в
`/etc/nginx/stream-sni-router.conf`. Сертификаты Let's Encrypt привязаны к именам, а не к IP, поэтому
перевыпускать их не нужно. Всё остальное решается двумя шагами: **DNS, затем команда `rebind-ip`**.

## Порядок

1. **Обновите A-записи ВСЕХ имён у регистратора** на новый IP:
   основной домен, домен Reality (если он отдельный), имя панели и имя XHTTP (если вы его включали).
   AAAA-записей быть не должно (nginx слушает только IPv4).

2. **Дождитесь, пока DNS обновится.** Проверка с любой машины:

   ```bash
   dig +short A ваш-домен @1.1.1.1
   ```

   В ответе должен быть новый IP.

3. **На сервере выполните:**

   ```bash
   sudo bash 3x-ui-dual-domain.sh rebind-ip
   ```

   Команда сама:
   - определяет текущий публичный IP (если не смогла — спросит его вручную);
   - сверяет A-записи всех имён и предупреждает (`WARN`), если какая-то ещё указывает на старый IP;
   - делает бэкап `stream-sni-router.conf.backup.<время>`, правит `listen`, проверяет `nginx -t`,
     перезапускает nginx и убеждается через `ss`, что nginx слушает `новый-IP:443`;
   - ничего не меняет, если `listen` уже указывает на нужный IP (можно запускать повторно).

4. **Проверьте схему:**

   ```bash
   bash 3x-ui-dual-domain.sh healthcheck
   ```

   Блок `[2]` (nginx и xray на 443) и проверка decoy-сайтов должны быть зелёными.

## Если что-то пошло не так

- `nginx -t` не прошёл или nginx не поднялся на новом IP: верните бэкап и перезапустите nginx.

  ```bash
  sudo cp /etc/nginx/stream-sni-router.conf.backup.<время> /etc/nginx/stream-sni-router.conf
  sudo nginx -t && sudo systemctl restart nginx
  ```

- Клиенты не подключаются, хотя `rebind-ip` отработал: чаще всего DNS ещё не обновился у
  провайдера клиента. Подождите или временно проверьте с другого DNS.

## Что проверить вручную

`rebind-ip` правит только nginx на самом сервере. Если у вас где-то стоит **сам IP вместо имени**, поменяйте его:

- каскадные ноды: в аутбаунде на другой ноде в поле «Адрес» указан IP этого сервера;
- клиентские конфиги, где в качестве адреса сервера вписан IP, а не домен;
- если сервер входит в флот с одним ботом ([tools/hub/README.md](../tools/hub/README.md)), поправьте адрес ноды
  в `/etc/tgbot/nodes.conf` на хабе.
