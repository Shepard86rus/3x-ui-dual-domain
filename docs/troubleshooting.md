# Если что-то не так

Первым делом — `bash 3x-ui-dual-domain.sh healthcheck`: он покажет, что именно
сломалось.

| Симптом | Причина / лечение |
|---|---|
| Decoy №2 отдаёт 301-цикл в TLS-режиме | fallback уехал на :80 — чинится в v0.4.0+; обновите скрипт (`upgrade`) |
| xray в краш-лупе, в логе `invalid geodata asset file` | зеркало отдало 404 на гео-файл — гео-страж (v0.4.2+) докачивает сам; проверьте healthcheck |
| AWG-инбаунд не поднимается, `interface already up` | баг панелей до lucx.289 — обновите панель (`x-ui update`), она поднимет осиротевший интерфейс за ≤10 с |
| healthcheck FAIL «слушает и разрешён ufw, но НЕ из схемы» | что-то слушает публичный порт вне белого списка (22/80/443) — сайдкар/тестовый инбаунд; уберите или внесите в `/root/.lucx-public-tcp-ports.txt` осознанно |
| Пропали клиенты инбаунда после правки через форму | перезапись `settings.clients` — клиенты восстанавливаются из бэкапа БД (`/etc/x-ui/x-ui.db`), инбаунд пересоздать |
| Всё сломалось после нажатия «Masking» | см. красное предупреждение вверху; запустите `healthcheck`, не чините вручную |
| Клиент не подключается, нет flow | у VLESS+TLS должен быть `flow=xtls-rprx-vision` — пересоздайте/обновите клиента |
| `install` на новом сервере предложил «обновить систему и перезагрузить» (блок «Проверка ядра», 0.5.8+) | устаревшее ядро: согласитесь (Enter), после перезагрузки запустите `install` ещё раз. До 0.5.8 такой сервер перезагружался посреди установки — запустите `install` заново |
| `install` упал на шаге [9/10]: `could not build map_hash, you should increase map_hash_bucket_size: 32` (v0.5.8 и старше, на VPS, где nginx не определяет процессор) | скачайте скрипт из релиза v0.5.9+ и запустите `install` заново: размеры хешей nginx теперь заданы явно. Домены длиннее 100 символов скрипт не принимает |
| `install` «завис» на шаге [5/10] после `Collecting pyasynchat` (Ubuntu 24.04+; у сервера есть IPv6, но до PyPI он не ходит) | скачайте скрипт из релиза v0.6.0+: в конце шага [2/10] он проверяет PyPI и, если IPv6 в таймауте, а IPv4 работает, ставит приоритет IPv4 в `/etc/gai.conf` (IPv6 не отключается). Правка действует для всей системы, кроме программ на Go: например, `localhost` может резолвиться в `127.0.0.1` раньше `::1`; файл — конфиг пакета libc-bin, при конфликте на обновлении `apt` может спросить, какую версию оставить (оставьте свою). Если PyPI недоступен совсем — установка не остановится, но IP-лимит (fail2ban) может не заработать. Пропуск проверки: `SKIP_PYPI_PREFLIGHT=1`. Вручную на старой версии: `sysctl -w net.ipv6.conf.all.disable_ipv6=1` и `install` заново |
| `install` сразу остановился: «СТОП: сервер не достучался до GitHub» (0.6.7+) | с сервера недоступен GitHub (или исчерпан лимит запросов API для вашего IP): повторите через несколько минут, проверьте `curl -I https://github.com` с сервера. Принудительно продолжить на свой риск: ответ `n` на вопрос о проверке или `SKIP_GITHUB_PREFLIGHT=1` |
| healthcheck WARN «Путь панели стандартный /panel/» (сервер поставлен версией ≤ 0.6.0) | страницу входа легко найти: обновите скрипт (`upgrade`) и выполните `bash 3x-ui-dual-domain.sh panel-path` — путь станет случайным (≈10 секунд, с бэкапом и автооткатом, подписки клиентов не меняются). Новый адрес печатается в конце и записан в `/root/.lucx-credentials` (строка `URL`). Включите также 2FA в настройках панели |
| Панель не открывается или зависает (часть файлов грузится, крупные скрипты висят в `pending`), а по SSH на сервер зайти можно (в том числе на свежей установке) | скорее всего провайдер режет или душит TLS до иностранного IP. Откройте панель через SSH-туннель: `sudo bash 3x-ui-dual-domain.sh panel-tunnel` (0.6.2+) напечатает готовую команду `ssh -N -L 8443:127.0.0.1:ПОРТ ПОЛЬЗОВАТЕЛЬ@СЕРВЕР` (пользователя подставляет команда) и настройку Termius (Port Forwarding → Local); затем откройте адрес, который напечатает команда (обычно `http://127.0.0.1:8443/ПУТЬ/`). Если входите на сервер по ключу, добавьте в команду `-i путь_к_ключу`; в Termius промежуточный хост — тот же сервер, на котором запущена команда. Команда только читает настройки, ничего не меняет, обычный доступ остаётся. Подтвердить причину: проверьте с другой сети (например, мобильный интернет другого оператора) |
| `restore`: «версия панели здесь … НИЖЕ архивной» / «домены не совпадают» / «nginx -t не прошёл» / «неверный пароль» (0.6.4+) | обновите панель (`x-ui update`); поставьте `install` с теми же доменами; после отката не перезагружайте сервер, если написано «nginx -t НЕ проходит». Полная таблица сообщений и порядок переноса: [docs/migration.md](migration.md) |
| Сервер «тупит», SSH отваливается по таймауту, `ss -s` показывает тысячи соединений, healthcheck: «conntrack … заполнена» (0.6.9+) | таблица отслеживания соединений (conntrack, по умолчанию 8192) забита, чаще всего чужим потоком «пустых» подключений на 443: смотрите `cat /proc/sys/net/netfilter/nf_conntrack_count`, `ss -Htn state established '( sport = :443 )' \| awk '{print $4}' \| sed 's/:[0-9]*$//' \| sort \| uniq -c \| sort -rn \| head`; поднимите таблицу: `sudo bash 3x-ui-dual-domain.sh conntrack-guard`; источник блокируйте на уровне `ufw insert 1 deny from <IP>` и пишите абузу хостера |
| Забыл адрес панели | `grep '^URL:' /root/.lucx-credentials` |
| `upgrade`: «уже выполняется (другой процесс)» | запущен второй `upgrade` (0.5.7+); дождитесь первого |
| XHTTP+Reality не подключается из mihomo / Clash Verge / XKeen (клиент на Xray работает) | известное ограничение: Xray-core ≥ 26.9.8 требует ML-KEM, а mihomo с отпечатком firefox его не отправляет. Лечится форком Mihomo Prizrak-Core (XKeen-UI → Настройки → Обновления → «Источник Mihomo»). Причины и обходы — [docs/xhttp.md](xhttp.md#если-клиент-не-подключается) |
