# 3x-ui-dual-domain

**Автор: Shepard86rus**
Разработка ведётся совместно с ИИ-ассистентом (**ZCode AI** / Claude).

Установщик и healthcheck для VPN-панели на одном сервере: два домена,
nginx SNI-роутинг на 443, режимы TLS/Reality, Hysteria2, AmneziaWG, подписки,
decoy-сайты, ufw + fail2ban.

> **Disclaimer.** Инструмент для управления собственным сервером. Используйте
> в соответствии с законодательством вашей страны.

---

## Как устроена схема (коротко)

- Снаружи слушает **только nginx на 443** (TCP): по SNI из ClientHello он
  маршрутизирует трафик на xray, слушающий на loopback (proxy protocol),
  а «чужие» подключения и браузеры получают decoy-сайты с валидным сертификатом.
- Панель и подписки доступны только через nginx по своим домену/пути,
  на публичных портах не висят.
- Hysteria2 работает на UDP/443, AmneziaWG — на отдельном UDP-порту
  (генерируется случайно при установке).
- ufw закрыт наглухо, кроме 22/80/443 TCP + 443 UDP + AWG-порта;
  fail2ban следит за SSH и панелью.

## ⚠️ После установки: что можно делать в панели, а что нельзя

Панель — полноценная, но схема держится на соглашениях, которые прописал
установщик. Краткое правило: **клиентов трогать можно, инбаунды и ядро — нет.**

### ✅ Безопасно

- добавлять / удалять / переименовывать **клиентов** через панель;
- включать и настраивать **подписки** (`subURI`, `subAwgEnable`);
- настраивать **Инси** (автоопределение, Sort-Order, Hide-Url, DoH);
- менять **порт/путь панели** (штатный переезд, healthcheck это допускает);
- обновлять панель (`x-ui update`) — патч-релизы своей минорной линии.

### ❌ Ломает схему (проверено на живых серверах)

- **Редактировать боевые инбаунды через форму и «Сохранить».** Форма
  перезаписывает `streamSettings` целиком: теряются `sockopt.acceptProxyProtocol`
  и массив `settings.clients` — инбаунд остаётся без единого клиента, весь
  трафик уходит в fallback. Правка инбаунда — только через **«Расширенный
  шаблон» (JSON)** или скрипт.
- **Переключать режим 443 (TLS ⇄ Reality) руками в панели.** Перенос схемы —
  работа для `add-vls` / `add-reality`: они переносят fallback, decoy-вхост
  и профиль healthcheck целиком.
- **Включать Masking (caddy-layer4) на 443** — конкурирует с nginx SNI-роутингом.
  Healthcheck увидит перехват и выдаст WARN.
- **Вешать инбаунды/сайдкары на порт 8443** — он занят внутренним вхостом
  панели (nginx на 127.0.0.1:8443); сайдкар на 8443 уходит в краш-луп.
  Свободные альтернативы: 2087, 2083, 9443.
- **Делать «двойной vless» (TLS + Reality) за одним 443** — БД панели хранит
  один порт на инбаунд, отдельного внешнего порта в схеме нет; клиентская
  ссылка сгенерируется с внутренним портом. Разные режимы — на разных серверах.
- **Править «Исходящие»/«Маршрутизацию» без кнопки «Сохранить».** Диалоги
  панели держат изменения только в превью: без «Сохранить» слева вверху и
  перезапуска панели всё исчезает (грабля дважды, обе — с болью).

## Два домена — зачем именно два

Скрипту нужны ровно **два имени** с A-записями на IP сервера — и это должны быть
**разные** имена:

| Домен | Для чего служит | Пример |
|---|---|---|
| **Панельный** | доступ к панели (только ты), decoy-сайт №1, подписки клиентов (`subURI`) | `panel.example.com` |
| **Основной** | клиентские подключения vless/hy2, decoy-сайт №2 | `example.com` |

Почему нельзя обойтись одним: nginx на 443 маршрутизирует трафик **по SNI** —
каждому сервису нужно собственное имя. Панели вдобавок нужно отдельное имя для
опсеки: адрес панели не светится на домене, куда ходят клиенты.

Домены — любые (регистратор любой). Главное: A-записи обеих имён → IP сервера
и рабочий резолвинг **до** установки — скрипт проверяет и без DNS не продолжит.

## Выбор режима 443: TLS или Reality

При `install` скрипт спросит режим работы порта 443.

**Оба режима рабочие из России** — выбор по вкусу: TLS — исторический выбор флота
и проще в диагностике, Reality — более сильная маскировка. Решение не окончательное:
переключается в любой момент без переустановки.

| | TLS | Reality |
|---|---|---|
| Как работает | TLS терминирует nginx на 443, xray внутри на loopback, «чужие» подключения уходят на decoy №2 | xray сам терминирует Reality-протокол, «чужие» подключения — на decoy №2 |
| Настройка клиента | vless+TLS, raw, fp=firefox, flow=none | vless+Reality, fp=firefox |
| Из России | ✅ работает | ✅ работает |

Передумать — не проблема: `add-vls` (→ TLS) или `add-reality` (→ Reality)
переключает режим в обе стороны **без переустановки**, клиенты и ключи сохраняются.

## Установка

Требования: Ubuntu 22.04/24.04, root, **два домена** (см. выше) с A-записями
на IP. DNS должно уже резолвиться — скрипт проверяет.

```bash
bash 3x-ui-dual-domain.sh install
```

Если скрипт лежит в другом месте — указывайте полный путь,
например: `bash /root/3x-ui-dual-domain.sh install`.

Скрипт интерактивный: спросит домены и режим 443 (TLS/Reality), предложит
выбор версии панели (Enter = последняя стабильная), в конце сохранит креды
в `/root/.lucx-credentials` (mode 600) и напечатает итог.

> ⚠️ **healthcheck — только после ПОЛНОЙ настройки панели.** Сразу после
> `install` ключей и части инбаундов ещё нет — проверка покажет FAIL'ы,
> и это будет ожидаемо, а не поломка. Порядок: `install` → настройка панели
> (клиенты, ключи, AWG) → `healthcheck`.

## Команды

| Команда | Что делает |
|---|---|
| `bash 3x-ui-dual-domain.sh install` | полная установка с нуля |
| `bash 3x-ui-dual-domain.sh healthcheck` | 60+ проверок: сервисы, порты, ufw, nginx, серты, decoys, БД, подписки, AWG, скан открытых портов |
| `bash 3x-ui-dual-domain.sh add-vls` | перевод схемы на TLS (из Reality), с fallback-вхостом |
| `bash 3x-ui-dual-domain.sh add-reality` | перевод схемы на Reality (из TLS) |
| `bash 3x-ui-dual-domain.sh add-hy2` | добавление Hysteria2-инбаунда (с preflight-проверкой порта) |
| `bash 3x-ui-dual-domain.sh rebind-ip` | сервер сменил IP — перепрописать конфиги |

## Обновление панели

```bash
x-ui update
bash 3x-ui-dual-domain.sh healthcheck
```

**Неинтерактивно** (cron/скрипты, без терминала) — обновление задаёт **два вопроса**:
подтверждение обновления (`y`) и обязательное SSL-меню (`4` = Skip SSL — панель за
вашим nginx). Без ответов: подтверждение = тихая отмена, а пустой ответ в SSL-меню
ставит Let's Encrypt-сертификат через порт 80 и зависает. Правильно:

```bash
printf 'y\n4\n' | x-ui update
```

После обновления проверьте факт, а не exit-код — версия должна смениться:

```bash
grep -aoE 'v3\.9\.0-lucx\.[0-9]+' /usr/local/x-ui/x-ui | tail -1
```

Патч-релизы своей минорной линии безопасны. Перед мажорными релизами
(смена схемы БД) сверьтесь с release notes панели — миграции необратимы.

## Переезд на новый IP

У регистратора поменяйте A-записи, затем:

```bash
bash 3x-ui-dual-domain.sh rebind-ip
```

## Типичные проблемы

| Симптом | Причина / лечение |
|---|---|
| Decoy №2 отдаёт 301-цикл в TLS-режиме | fallback уехал на :80 — чинится в v0.4.0+; обновите скрипт |
| xray в краш-лупе, в логе `invalid geodata asset file` | зеркало отдало 404 на гео-файл — гео-страж (v0.4.2+) докачивает сам; проверьте hc |
| AWG-инбаунд не поднимается, `interface already up` | баг панелей до lucx.289 — обновите панель (`x-ui update`), она поднимет осиротевший интерфейс за ≤10 с |
| hc FAIL «слушает и разрешён ufw, но НЕ из схемы» | что-то слушает публичный порт вне белого списка (22/80/443) — сайдкар/тестовый инбаунд; уберите или внесите в `/root/.lucx-public-tcp-ports.txt` осознанно |
| Пропали клиенты инбаунда после правки через форму | та самая перезапись `settings.clients` — клиенты восстанавливаются из бэкапа БД (`/etc/x-ui/x-ui.db`), инбаунд пересоздать |
