Установщик и проверка (healthcheck) для панели на собственном сервере: два домена,
nginx на 443 (снаружи отвечает только он, h2 включён; xray Reality за ним), VLESS+Reality (Vision), Hysteria2, AmneziaWG, подписки,
decoy-сайты, ufw + fail2ban. Опционально — Telegram-бот управления нодой.

## Что вы получите

- Снаружи слушает **только nginx на 443**: панель и подписки не висят на публичных портах,
  а чужие подключения и браузеры видят обычный сайт-заглушку (decoy).
- На порту 443 работает **VLESS+Reality (Vision)** по схеме «Reality-only» (с 0.7.0): TLS-инбаунда xray нет, снаружи отвечает только настоящий nginx, а xray Reality стоит за ним; браузеры, сканеры и чужой SNI получают сайт-заглушку (по h2). Рядом — Hysteria2 (UDP/443) и AmneziaWG. Прежняя схема с TLS-инбаундом — `TLS_MODE=1`.
  Необязательно — третий вход **XHTTP+Reality** на отдельном имени ([docs/xhttp.md](docs/xhttp.md)).
- Закрытый firewall (ufw) и fail2ban на SSH и панель.
- Команда `healthcheck` проверяет весь сервер и говорит, что сломалось.
- Команды `backup` и `restore` переносят установку целиком (клиенты, ключи, подписки) на другой сервер или откатывают её к снимку, не создавая клиентов заново ([docs/migration.md](docs/migration.md)).

Подробно, как всё устроено и зачем два домена — [docs/scheme.md](docs/scheme.md).

## Быстрый старт (по порядку)

| Этап | Что делаем |
|---|---|
| 1. Подготовка | сервер, домены и DNS, обновление системы |
| 2. Установка | скачать скрипт и запустить его без аргументов: меню, пункт `1` (install) |
| 3. Панель | обновить ключи у созданных клиентов и (по желанию) создать инбаунд AmneziaWG (вручную, в браузере) |
| 4. Проверка | `healthcheck` |
| 5. Клиенты | поставить приложение (Happ) и добавить подписку |

**Этап 1. Подготовка.** Нужен сервер с Ubuntu 22.04/24.04 (root) и **два домена** с A-записями на IP сервера
(DNS должен резолвиться до установки): панельный — для панели и подписок, основной — для клиентов. Третье имя для
XHTTP — по желанию (тоже с A-записью на этот сервер). На свежем сервере первым делом обновите систему:

```bash
apt update && apt full-upgrade -y && reboot     # после перезагрузки зайдите снова под root
```

**Этап 2. Установка.** Скачайте скрипт последнего РЕЛИЗА (он остаётся на сервере, все команды запускаются из него)
и запустите его без аргументов: откроется меню. Выберите пункт `1` (install), прочитайте описание и введите `yes`: скрипт
спросит домены и всё сделает сам (третье имя для XHTTP — необязательно, Enter пропускает).

```bash
curl -fsSL https://github.com/Shepard86rus/3x-ui-dual-domain/releases/latest/download/3x-ui-dual-domain.sh -o 3x-ui-dual-domain.sh
bash 3x-ui-dual-domain.sh
```

Подробнее о каждом пункте меню (`?номер` показывает описание и подводные камни): [docs/menu.md](docs/menu.md). Установку можно запустить и без меню, одной командой: `bash 3x-ui-dual-domain.sh install`.

Если в начале предложит обновить систему и перезагрузиться — согласитесь и запустите `install` ещё раз. Если в
конце попросит перезагрузку — перезагрузитесь: после установки нового ядра AmneziaWG заработает только после неё.
Логин и пароль панели покажет итоговый экран — сохраните его. На нём же блок «Проверка установки» (службы, порты, DNS, сертификаты, подписка, AWG, ufw: ✓/⚠/✗ с подсказками) и шаги, что сделать дальше.

Установщик сам создаёт Reality, Hysteria2 (и XHTTP, если задали имя) с клиентами, подписки,
сертификаты, decoy-сайты, ufw и fail2ban.

**Этап 3. Панель — два шага вручную:** **обновить все ключи у созданных клиентов** (UUID, пароль, ID подписки,
Hysteria Auth) и, если AmneziaWG нужен, создать инбаунд «AmneziaWG (LucX)». Автор не рекомендует пользоваться
AmneziaWG из-за массовых банов. Подробно, с таблицей полей: **[docs/install.md](docs/install.md#этап-3-настройка-панели-вручную)**.

**Этап 4. Проверка.** Запускайте **после** этапа 3: до него часть проверок может быть красной — это ожидаемо, а не
поломка.

```bash
bash 3x-ui-dual-domain.sh healthcheck
```

**Этап 5. Клиенты.** Ссылку подписки выдавайте только после этапа 3. Сейчас рекомендуем **[Happ](https://github.com/Happ-proxy)**
(Android, iOS, Windows, macOS, Linux; проверен с нашей подпиской). Ссылки подписки (SUB для Happ и INCY, CLASH для Clash Verge) берутся в панели: Клиенты → кнопка ⓘ → «Информация о подписке». Для AmneziaWG подписки нет: конфиг берётся там же, в блоке «AWG-конфиг». Где скачать приложение и как добавить подписку — в **[docs/clients.md](docs/clients.md)**.

> ⚠️ **Временно не рекомендуем INCY и Clash Verge Rev.** У INCY на только что установленном приложении подписка с маршрутизацией может не запускаться (ошибка «code "TORRENT" not found in loaded geodata»): без правил весь трафик, включая российские сайты, пойдёт через VPN. Мы разбираемся. Clash Verge Rev на обычном ядре mihomo не подключается к Reality, а в схеме 0.7.0 других TLS-входов, кроме Hysteria2, нет. Когда ситуация изменится, этот блок будет обновлён.

## Команды

> ⚠️ **Не запускайте всё подряд.** Установщик сам включает всё нужное: Reality (Vision) на 443, Hysteria2 и AmneziaWG. Команды из разделов «По желанию» и «Служебные команды» нужны только в описанных случаях. Если запустить такую команду «на всякий случай», скрипт, как правило, ответит «уже включён — ничего не делаю». Это нормально, ничего не сломано, но и пользы нет.

### Нужны всем

| Команда | Когда запускать |
|---|---|
| `sudo bash 3x-ui-dual-domain.sh` | Без аргументов в терминале открывает меню (с v0.6.8): все основные команды с описанием, вариантами и подводными камнями по `?номер`, опасные пункты просят ввести `yes`. Подробно: [docs/menu.md](docs/menu.md) |
| `bash 3x-ui-dual-domain.sh healthcheck` | Проверка сервера (90+ проверок: сервисы, порты, ufw, nginx, сертификаты, заглушки, БД, подписки, AWG, бот). Запускайте после установки, после любых обновлений и когда что-то не работает. Ничего не меняет |
| `bash 3x-ui-dual-domain.sh upgrade` | Обновить сам скрипт до последнего релиза (с проверкой sha256). Запускайте, когда вышла новая версия |
| `bash 3x-ui-dual-domain.sh panel-tunnel` | Если панель по `https://домен/путь/` не открывается или зависает (часть провайдеров режет TLS до иностранных IP), а по SSH на сервер зайти можно: печатает готовую команду `ssh -L` и настройку Termius для входа через SSH-туннель. Ничего не меняет на сервере, обычный доступ остаётся |
| `sudo bash 3x-ui-dual-domain.sh backup` / `restore файл` | Перенос на другой сервер или откат к снимку: зашифрованный архив (клиенты, инбаунды, настройки, конфиги) и восстановление из него. Подробно, с готовыми командами: раздел [«Перенос на другой сервер»](#перенос-на-другой-сервер-и-резервная-копия-backup--restore) ниже и [docs/migration.md](docs/migration.md) |

#### Панель не открывается или зависает (`panel-tunnel`)

**Когда это нужно.** Вы заходите на `https://ваш-домен/путь/`, а страница не открывается или открывается наполовину: часть файлов грузится, крупные скрипты висят в состоянии `pending` (так видно во вкладке «Сеть» браузера). При этом на сервер по SSH вы зайти можете. Чаще всего так делает провайдер: режет или душит TLS-соединения до иностранных IP. Особенно неприятно на свежей установке: без панели нельзя создать первого клиента.

**Что делать.** Зайти в панель через SSH-туннель: трафик идёт внутри SSH и проверку по имени сайта (SNI) не проходит.

1. На сервере (по SSH): `bash 3x-ui-dual-domain.sh upgrade`, затем `bash 3x-ui-dual-domain.sh panel-tunnel`. Команда ничего не меняет, а печатает готовую строку для вашего сервера: с вашим IP, портом панели и путём.
2. На **своём компьютере** (Windows PowerShell, macOS, Linux) выполните напечатанную команду вида `ssh -N -L 8443:127.0.0.1:ПОРТ ПОЛЬЗОВАТЕЛЬ@СЕРВЕР` (пользователя команда подставит сама; если входите по ключу, добавьте `-i путь_к_ключу`) и **оставьте окно открытым**.
3. В браузере откройте напечатанный адрес вида `http://127.0.0.1:8443/ПУТЬ/`. Это та же панель, логин и пароль прежние. Адрес без «замка» — это нормально.

Если вы пользуетесь Termius: раздел **Port Forwarding → New Forwarding → Local**, локальный порт 8443, адрес привязки (Bind address) 127.0.0.1 (не 0.0.0.0), промежуточный хост (Intermediate host) — **тот же сервер, на котором вы запустили команду**, адрес назначения 127.0.0.1, порт назначения — порт панели из вывода команды; затем **Start**.

**Что важно знать.**
- Нужен SSH-доступ к серверу (он нужен и для установки). Если провайдер режет и сам SSH, туннель не поможет.
- Туннель работает, пока открыто окно `ssh` (закрыть: `Ctrl+C`, в Termius — Stop). Держать его постоянно не нужно, только когда заходите в панель.
- Обычный доступ по `https://домен/путь/` остаётся как был: у тех, у кого он работает, ничего менять не нужно.
- Если порт 8443 на вашем компьютере занят, возьмите другой (например 18443) и подставьте его в адрес браузера.
- Если в `sshd` запрещена пересылка портов (`AllowTcpForwarding no`), команда предупредит об этом.
- Чтобы убедиться, что дело в провайдере, откройте панель с другой сети (например, мобильный интернет другого оператора).

### Перенос на другой сервер и резервная копия (`backup` / `restore`)

Версия 0.6.4 и новее. Нужны, если вы меняете хостера, восстанавливаете упавший сервер или хотите подстраховаться перед рискованным действием. Клиентам ничего не переустанавливать: домены, ключи, ссылки подписок остаются прежними.

**Коротко, перенос на другой сервер:**

1. **Старый сервер:** `sudo bash 3x-ui-dual-domain.sh backup`. Задайте пароль архива (минимум 8 символов, **восстановить его нельзя**), скачайте файл `….lucxbak` на свой компьютер (SFTP или `scp`) и сразу загрузите на новый сервер **по его IP**.
2. **DNS:** у регистратора направьте A-записи **всех** имён схемы на IP нового сервера, подождите (`dig +short A домен`). С этого момента и до `restore` у клиентов с обновлённым DNS подключения нет (на новом сервере до `restore` чужая установка), поэтому шаги 2–4 делайте подряд (около 10–20 минут, время `install`).
3. **Новый сервер:** `install` с **теми же** доменами (и `add-xhttp <то же имя>`, если на старом был XHTTP). Ручную настройку панели (этап 3) делать не нужно: БД придёт из архива.
4. **Новый сервер, в `tmux`:** выполните `sudo bash 3x-ui-dual-domain.sh restore файл.lucxbak`.
5. **Проверка:** `healthcheck`, вход в панель **старыми** логином и паролем, подключение с телефона. Старый сервер выключайте не сразу.

**Откат к снимку на том же сервере:** `backup` перед обновлением или экспериментом, при проблеме `restore` этого файла.

**Главное, что нужно знать:**
- архив содержит ключи и всех клиентов: храните как секрет, пароль отдельно, восстанавливайте только **свои** архивы;
- домены на новом сервере должны совпадать с архивными, версия панели там не ниже архивной (`x-ui update`);
- `restore` сам проверяет архив до изменений и при любой ошибке или обрыве возвращает прежнее состояние (страховочная копия в `/root/.lucx-restore-backup-*`; после проверки удалите её, там секреты);
- в архив не входят сертификаты (`install` на новом сервере выпускает свои; ключ `--with-certs` кладёт в архив и их), Telegram-бот (его токен вводится заново: `add-bot`), заглушки, правила ufw и fail2ban: базовое ставит `install`, порты, открытые вами вручную, откройте заново.

Все шаги с примерами команд и вывода, проверка после переноса, параметры и разбор ошибок: **[docs/migration.md](docs/migration.md)**.

### По желанию (даже на свежей установке этого может не быть)

| Команда | Что делает и когда нужна |
|---|---|
| `bash 3x-ui-dual-domain.sh add-xhttp <имя>` / `remove-xhttp` | Третий вход XHTTP+Reality на отдельном имени (нужна A-запись на этот сервер, см. [docs/xhttp.md](docs/xhttp.md)). Нужен, только если вы этого хотите. На установке его спрашивали необязательным вопросом: если уже ответили именем, команда не нужна |
| `sudo bash 3x-ui-dual-domain.sh reality-only` / `reality-only status` | Перевести **уже работающий** сервер, поставленный до 0.7.0 (TLS-инбаунд, при желании с Reality перед ним), в схему Reality-only; `status` показывает текущий режим и ничего не меняет. Само сливает клиентов, делает бэкап БД и конфига (`/root/.lucx-reality-only/`), проверяет Reality-клиентов и при любом сбое откатывает. Старые ссылки со `security=tls` перестанут работать — клиентам нужно обновить подписку. Новая установка уже Reality-only, команда ей не нужна. Подробно: [docs/service-commands.md](docs/service-commands.md) |
| `bash 3x-ui-dual-domain.sh add-bot` / `remove-bot` | Поставить или удалить Telegram-бота управления. Нужен, если не поставили его при установке |
| `bash 3x-ui-dual-domain.sh add-swap` / `remove-swap` | Swap-файл для сервера с малой памятью (около 1 ГБ). `healthcheck` сам подскажет, если он нужен |
| `bash 3x-ui-dual-domain.sh rebind-ip` | Только если сервер сменил IP: перепрописать конфиги (порядок действий: [docs/ip-change.md](docs/ip-change.md)) |
| `bash 3x-ui-dual-domain.sh conntrack-guard` | Поднять таблицу conntrack (0.6.9+) на уже работающем сервере: защита от флуда, из-за которого забивается таблица (на малых ВМ часто 8192) и сервер «тупит». Меняет только параметры ядра, nginx и клиентов не трогает; install делает то же сам; `worker_connections 16384` и `proxy_connect_timeout 5s` ставит только новый install (на работающем сервере не применяются) |

### Служебные команды (обычно не нужны)

Установщик сам включает всё, что нужно: случайный путь панели, Reality-only на 443 и Hysteria 2 (серверы, поставленные до 0.7.0, переводит команда `reality-only`). Эти команды остаются в скрипте только для двух случаев: сервер поставлен старой версией или какой-то шаг установки не прошёл и установщик написал «позже: ...». Описание и порядок действий: **[docs/service-commands.md](docs/service-commands.md)**. Если не уверены, запустите `healthcheck`: он сам подскажет, нужна ли такая команда.

### Проверка IP: в какой стране его видят

Отдельный скрипт [`tools/ipregion-lucx.sh`](tools/ipregion-lucx.sh) (форк [ipregion](https://github.com/Davoyan/ipregion), MIT) показывает, какой страной IP считают GeoIP-сервисы, YouTube, ChatGPT, Netflix и др., и помечен ли он как VPN/хостинг. Запуск по ссылке, ничего не устанавливая:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Shepard86rus/3x-ui-dual-domain/main/tools/ipregion-lucx.sh)            # IP этой машины
bash <(curl -fsSL https://raw.githubusercontent.com/Shepard86rus/3x-ui-dual-domain/main/tools/ipregion-lucx.sh) 1.2.3.4    # чужой IP, например до покупки
bash <(curl -fsSL https://raw.githubusercontent.com/Shepard86rus/3x-ui-dual-domain/main/tools/ipregion-lucx.sh) --expect RU # сверить со страной, код выхода 3 если не совпало
```
### Версии и обновление

Версии скрипта и релизы — на странице [Releases](https://github.com/Shepard86rus/3x-ui-dual-domain/releases).
Скрипт `upgrade` скачивает релиз и сверяет sha256; версии ≤0.5.4 качали `main` без проверки — обновите их до 0.5.5 или новее.
`upgrade` заменяет только сам скрипт и схему работающего сервера не меняет: чтобы перейти на Reality-only (0.7.0), после `upgrade` запустите `sudo bash 3x-ui-dual-domain.sh reality-only` (заранее: `reality-only status`; перевод занимает около минуты, x-ui перезапускается).

> ℹ️ **Клиенты на ядре mihomo** (Clash Verge, XKeen на роутерах) могут не подключаться к Reality и XHTTP+Reality на свежем Xray (≥ 26.9.8); клиенты на Xray (Happ и др.) работают; на роутере с XKeen-UI помогает источник Mihomo Prizrak-Core. Причины и обходы — в [docs/xhttp.md](docs/xhttp.md#если-клиент-не-подключается).

## Что можно и что нельзя в панели

**Клиентов трогать можно; инбаунды, их режимы и настройки ядра Xray в панели — не трогать.**
Правки через форму инбаунда и кнопка «Masking» ломают схему. Полный список — в [docs/panel-rules.md](docs/panel-rules.md).
